# Security

Do not post credentials, customer documents or an exploitable vulnerability in a public issue. Use the repository's private vulnerability reporting channel when the maintainer has enabled it. Until a private contact channel is published, request one without including sensitive details.

Every operator is responsible for keeping their deployment updated and configuring authentication, permissions, backups and resource limits. The local development server and development identities must never be exposed as production authentication.

This initial source preparation is not a completed independent security audit. A successful build or test suite does not establish that every deployment is secure.
